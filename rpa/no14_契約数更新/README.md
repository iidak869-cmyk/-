# No.14 契約数更新（ほうこっくん → プロダクト日報 → スプシ）

ほうこっくんの「前日/当日 × 新規/リピート」4パターンの営業報告を自動収集し、
プロダクト日報「入力」シートへ転記（重複チェック付き）、追記分をスプシへも自動反映する。
毎日9時にタスクスケジューラで自動実行。

## ファイル構成（配置先: C:\Users\iida869\Desktop\rpa-playwright\no14_契約数更新）

| ファイル | 役割 |
|---|---|
| 契約数更新.js | 本体（Playwright）。収集→転記→スプシ反映 |
| 転記_com.ps1 | Excel本体(COM)でセルを書き込む補助スクリプト（本体から自動で呼ばれる） |
| config.json | 接続先・ファイルパス・ログイン情報（ローカルのみ、コミット禁止） |
| 毎日実行.bat | タスクスケジューラから呼ぶ実行用バッチ（ログを実行ログ.txt に出力） |
| 追記分.csv | 実行ごとの追記内容ログ兼スプシ貼り付けの予備 |

## 実行方法

| コマンド | 動作 |
|---|---|
| `node .\契約数更新.js --dry-run` | どこにも書き込まず抽出結果の表示のみ |
| `node .\契約数更新.js` | 本番実行（Excel追記 → CSV → スプシ貼り付け） |
| `node .\契約数更新.js --探索` | Playwright Inspectorで画面調査 |

自動実行: タスクスケジューラ「RPA_契約数更新_毎朝9時」（毎日9:00、土日含む）

## 転記マッピング（「入力」シート）

| 列 | 内容 | 取得元 |
|---|---|---|
| A | 契約日（日付） | 一覧の営業日付 |
| C/D/E/F/H | 顧客名/営業担当者/営業部署/会社所在地/業種 | 報告詳細 |
| J | 画像（添付なし→「無」、あり→空欄） | 報告詳細の【画像】 |
| M | 金額（月額グロス、数値） | 【金額（税込）】 |
| O | クレカの有無（有/無） | 報告内容の「クレカ(所持/未所持)」 |
| AD/AE | 挨拶日/挨拶時間（HH:MM正規化） | 報告内容の「【挨拶zoom】日時」 |
| CH | 納品物件（Cyteki/DegiOne） | 【納品物件】 |

重複チェック: A列(契約日)+C列(顧客名)。ほうこっくんの報告一覧は
「その日に報告された契約」と「営業日付がその日の契約」が混在するため、
前日+当日の両方を回して重複チェックで二重転記を防ぐ（手作業と同じ運用）。

## 技術メモ（ハマりどころ）

1. **httpリダイレクト**: ほうこっくんはログイン後 `http://…/top/` へ飛ばすがポート80が
   閉じているため、httpをhttpsに強制置換するrouteを入れている。ログインPOSTは
   リダイレクトを追跡しない`fetch(redirect:manual)`方式。
2. **詳細ページのアクセス制限**: 「直前に表示した一覧に載っている報告」しか詳細を
   開けない（不正なアクセスです）。検索→即詳細の順で処理し、拒否時は一覧を開き直して再試行。
3. **Excel書き込みはCOM経由**: ExcelJSで大規模ブックを保存し直すと壊れる（修復ダイアログ）。
   読み取り（重複チェック）のみExcelJS、書き込みはExcel本体(COM)＝転記_com.ps1。
4. **待ち条件**: 画像/CDNの読み込み完了は待たない（domcontentloaded）。
5. **日付移動**: `/top/index.php?id=N`（Nは今日からのオフセット。前日=-1、当日=0）。

## 運用ルール

- 実行時間帯（9時前後）はプロダクト日報のExcelを開かない（COM書き込みが失敗する）
- PCは9時に起動・ログイン済みであること（間に合わない場合は起動後に自動実行される）
- セッション切れは自動再ログインで復旧（config.jsonのid/password使用）

## 本番切り替え手順

現在の書き込み先はテスト用。本番化は `config.json` の2か所を差し替えるだけ:
1. `productNippo.excelPath` → 本物のプロダクト日報のパス
2. `spreadsheet.url` → 本番スプシのURL
