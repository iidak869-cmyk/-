# 業務改善指示書 作成スキル

株式会社WeeAre デザイン課 飯田圭祐が毎週水曜に提出する「業務改善指示書」を、
対話形式で内容を確認しながらExcelファイルとして生成する。

## このスキルのゴール

- **対話を通じて**5つのセクションの内容を固める
- Claude が②③④⑤の**改善案を複数提案**し、ユーザーが選んだり自分の案を追加したりする
- 合意できたら `generate_kaizen.py` を使ってExcelを生成する

---

## ステップ1: 今週の事象をヒアリングする

まず以下を一問ずつ（または一度にまとめて）ユーザーに聞く。
答えの分量は問わない。キーワード程度でも受け取り、Claude側で肉付けして確認する。

```
聞くべき内容 (①セクション用):
1. 発生日はいつ？
2. 何が起きた？（発生内容）
3. どうやって発覚した？（発見経緯）
4. 関与者は誰？（本人のみ？チーム？）
5. 顧客・従業員への影響はあった？
```

ユーザーの答えをもとに「①の下書き」を組み立て、確認を取る。
修正があれば反映して再確認する。

---

## ステップ2: ②③④⑤の改善案を提案する（核心）

①の事象をもとに、Claude が以下を**複数案（2〜3案）**提案する。

### ② 想定リスク
- この問題が続いた場合の影響範囲を複数の視点（本人・チーム・顧客・納期など）から書く
- 例：同様のケースが他にもないか、潜在的な見落としがないかも触れる

### ③ 問題点（要因分析）
- 「人的ミス」「確認不足」で終わらせず、仕組み・体制・運用ルールの欠如に踏み込む
- 根本原因を複数の角度から提示する

### ④ 改善策（赤字セクション・重要）
- 短期対応（即実施できること）と中期対応（ルール化・仕組み作り）に分けて提案
- 具体的かつ現場で実践しやすい内容にする

### ⑤ 対策・行動（赤字セクション）
- 部門横断・経営判断が必要な長期視点の対策
- 「特になし」も選択肢として提示する

提案後、ユーザーに「この中から使いたいものを選んでください。自分の案があれば追加してください」と伝え、対話を継続する。

---

## ステップ3: 内容を確定する

すべてのセクション（①〜⑤）の内容が決まったら、最終確認として全文を表示する。

```
【最終確認】

① 認知されたミス・事例:
[内容]

② 想定リスク:
[内容]

③ 問題点（要因分析）:
[内容]

④ 改善策:
[内容]

⑤ 対策・行動:
[内容]

作成日: [今日の日付 "YYYY年M月D日" 形式]

これでよければ「OK」「生成して」などと言ってください。
```

---

## ステップ4: Excelファイルを生成する

ユーザーが確認OKを出したら、以下のスクリプトでExcelを生成する。

**スクリプトパス**: `scripts/generate_kaizen.py`（このスキルと同じディレクトリ）

```bash
python "<skill_dir>/scripts/generate_kaizen.py" \
  --date "YYYY年M月D日" \
  --incident "①の内容（改行は\nで）" \
  --risk "②の内容" \
  --cause "③の内容" \
  --improvement "④の内容" \
  --action "⑤の内容" \
  --output "業務改善指示書_YYYYMMDD.xlsx"
```

- 出力先はホームディレクトリ (`~/`) か、ユーザーが指定した場所
- ファイル名は `業務改善指示書_YYYYMMDD.xlsx` 形式
- 生成後は `SendUserFile` でファイルをユーザーに送る

---

## 注意事項

- **作成者は常に「飯田圭祐 / デザイン課」固定**
- **日付は実行日（今日の日付）**。ユーザーが別の日付を指定した場合はそちらを優先
- 内容はユーザーとの対話で決めた最終版を使う。Claude が勝手に変えない
- ④⑤のセクションラベルは赤字（テンプレート通り）— スクリプト側で制御済み
- Excel生成後、LibreOfficeによるrecalcは不要（数式なし）

---

## 対話のトーン

- 日本語で、丁寧だが堅すぎない口調
- 改善案を提示するときは「たとえばこんな案はどうでしょう？」のように柔らかく
- ユーザーが「特にない」「任せる」と言った場合はClaudeが適切な内容を代替する
- 「/grill^me」や「もっと深掘りして」と言われたら、より詳細な質問（発生の背景、体制の課題、再発防止の具体策）を追加で行う
